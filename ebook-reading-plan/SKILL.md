# Ebook Reading Plan Skill

解析一本 .epub 或 .mobi 电子书,询问用户每天可用的阅读分钟数,然后生成一份**按每日时间均分**的 Markdown 阅读计划——每天一个 `- [ ]` todo,带页码区间,长章节自动拆分。

## 设计原则

- **简单**:只问一个问题——每天读多少分钟。不问开始日期、截止日期、阅读偏好。
- **时间优先**:每天的阅读量按用户输入的分钟数切,长章节会被拆分到多天(用 `[i/N]` 标注),目标是每天的阅读时长接近一致。
- **标明页码**:每段标 `（P.X-Y）`(按估算每页字数换算),方便在 Kindle/纸书上对照。
- **不写日期**:计划只用 `Day 1 / Day 2 / ...` 编号 + 总天数估算。用户哪天开始、隔天读还是连读都不影响计划文件本身。
- **可复制到任务管理工具**:每行 todo 自包含(书名 + Day N + 章节 + 页码 + 估算时长)。

## 常量(写在 `scripts/parse_ebook.py` 顶部)

| 常量 | 默认值 | 含义 |
|------|--------|------|
| `SPEED_ZH` | 300 字/分钟 | 中文阅读速度 |
| `SPEED_EN` | 250 词/分钟 | 英文阅读速度 |
| `CHARS_PER_PAGE_ZH` | 600 字/页 | 估算中文每页字数 |
| `WORDS_PER_PAGE_EN` | 250 词/页 | 估算英文每页词数 |

用户想调整就改这四个常量,不要在 SKILL.md 里硬编码副本。

## 工作流程

### Step 1 — 拿到文件路径

用户通常会直接给出 `.epub` 或 `.mobi` 文件的本地绝对路径。如果没给,问一次:"请把电子书的本地路径发给我(支持 .epub / .mobi)"。

不要尝试去网上下载书,不要处理 URL,只接受本地文件。

### Step 2 — 解析目录(预览)

```bash
python3 ~/.claude/skills/ebook-reading-plan/scripts/parse_ebook.py "<book_path>"
```

脚本首次运行会自动 `pip install --user` 必要依赖(`ebooklib`、`beautifulsoup4`、`lxml`,mobi 文件再加 `mobi`)。

成功时输出 JSON,字段:`title`、`author`、`language`(zh/en)、`chapters[{index,title,length}]`、`total_length`。失败时输出 `{"error": "..."}`,把 error 转告用户。

用这一步的结果**简短**告诉用户:书名、作者(如有)、总章节数、估算总字数。

### Step 3 — 询问每天阅读时间

用 `AskUserQuestion` 问一次:

> 你每天计划花多少时间读这本书?

选项(单选):
- `15 分钟`
- `30 分钟`(推荐)
- `60 分钟`
- (用户可选 Other 自填,例如 45)

解析成整数 `daily_minutes`。

### Step 4 — 生成并写入 Markdown

直接让脚本生成并写入文件:

```bash
python3 ~/.claude/skills/ebook-reading-plan/scripts/parse_ebook.py "<book_path>" --schedule <daily_minutes>
```

默认输出路径 = 书所在目录 / `<书名>-reading-plan.md`。也可以加 `--output "<path>"` 显式指定。

脚本完成后会打印 `{"ok": true, "output": "...", "days": N}`,把这个路径告诉用户即可。

**不要**自己在主对话里手算调度——脚本已经实现了"按每天分钟数切日 + 长章节拆分 + 页码标注"的完整逻辑,跟着脚本走最稳。

### Step 5 — 报告结果

简短确认:已生成阅读计划,共 N 天,文件路径 `<path>`。如果想调整速度/每页字数,提示用户修改脚本顶部的常量再重跑。

## 生成的 Markdown 样例(节选)

```markdown
# 《XXX》阅读计划

**书籍**: 《XXX》
**作者**: YYY
**总章节**: 22
**估算总字数**: 172,620
**估算总页数**: 288 页（按每页 600 字估算）
**每天阅读**: 30 分钟（约 9,000 字）
**预计需要**: 19 天读完
**阅读速度参考**: 中文 300 字/分钟、英文 250 词/分钟

## 每日 Todo

- [ ] 《XXX》Day 1 · 约 30 分钟
  - 新版序言（P.1-3）
  - 新版前言（P.3-5）
  - 新版导论 [1/4]（P.5-15）
- [ ] 《XXX》Day 2 · 约 30 分钟
  - 新版导论 [2/4]（P.16-30）
...
- [ ] 《XXX》Day 19 · 约 14 分钟 ✅ 完成全书
  - 结束语（P.282-288）
```

**格式约定**:父级 todo 行只显示书名、Day 编号和总时长(用户主要扫这一行决定今天读多久),具体章节、页码作为子级 `-` bullet 缩进展示(细节但不抢视线)。复制到滴答清单等工具时,父子结构通常会自动保留为子任务。

## 边界与注意事项

- **DRM 加密**:解析会失败,如实告知用户。不要尝试破解。
- **目录为空**:有的电子书没有 toc,脚本退化成"按 HTML 文件顺序当作章节",此时章节标题可能是 `Section 1 / Section 2`,照常生成计划即可。
- **格式不支持**:azw3、pdf 等不支持,提示用户先用 Calibre 转换成 epub。
- **页码是估算值**:epub 本身没有固定页码,脚本按每页字数换算近似的"印刷版"页码。和 Kindle 屏幕上显示的位置不会精确一致,但量级正确,够对照用。
- **不存进度**:不要试图记忆"用户上次读到哪一天",每次都重新生成完整计划。
- **不要联网**:全部基于本地文件操作。
